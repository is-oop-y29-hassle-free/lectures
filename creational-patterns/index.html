Фабричный метод

Фабричный метод

Фабричный метод — это порождающий паттерн проектирования, который определяет общий интерфейс для создания объектов в суперклассе, позволяя подклассам изменять тип создаваемых объектов.
А. Швец, «Погружение в паттерны проектирования», с. 69
Также известен как „Виртуальный конструктор“

Фабрика

«Является» и «содержит»

Если наследование можно выразить словом «является» (автомобиль является транспортом), то композицию — словом «содержит» (автомобиль содержит двигатель).

Строитель

Строитель — это порождающий паттерн проектирования, который позволяет создавать сложные объекты пошагово. Строитель даёт возможность использовать один и тот же код строительства для получения разных представлений объектов.

3.6
Строитель

Зачем строитель, 1

объект остаётся неизменяемым, даже когда аргументов много.

  • Нет мутабельности ради сбора данных
  • Проще валидация в конструкторе
  • Пошаговое создание
3.7
Строитель

Зачем строитель, 2

клиент не видит «битых» объектов — строитель не отдаёт объект, пока тот не готов (книга, с. 115).

  • Значения по умолчанию — внутри строителя
  • Разные типы — общими вызовами строителя
  • Do 3, Do 10
3.8
Строитель

Главное правило реализации

строитель ни в какой момент не хранит готовый объект собираемого типа.

  • Атрибуты строителя повторяют параметры конструктора
  • Иначе в объект встраивается мутабельность ради строителя
  • Это самая частая ошибка — вернёмся к ней

3.12
Строитель

Convenience: шаги и Build

Build вызывает конструктор, а не заполняет готовый объект.

продолжение
public ServiceBuilder WithOne(IDependency1 one)
{
_one = one;
return this;
}
public ServiceBuilder WithTwo(IDependency2 two)
{
_two = two;
return this;
}
public ServiceBuilder WithThree(IDependency3 three)
{
_three = three;
return this;
}
public Service Build()
{
return new Service(
_one,
_two ?? throw new InvalidOperationException(),
_three ?? throw new InvalidOperationException());
}
}
На что смотреть

C++C#Для C++-человека

3.13
Строитель

Stateful Constructor builder

конструктор с состоянием — когда данные собираются по шагам.

  • Пример: коллекция, значения которой приходят из разных мест (разные View в UI)
  • Валидация — в строителе
  • Обычно — для моделей
3.14

Модель нельзя создать в обход строителя

Директор

Вы можете пойти дальше и выделить вызовы методов строителя в отдельный класс, называемый «Директором». В этом случае директор будет задавать порядок шагов строительства, а строитель — выполнять их.
А. Швец, «Погружение в паттерны проектирования», с. 105
По книге там же: отдельный класс директора не является строго обязательным.

4.1
Прототип

Прототип

Прототип — это порождающий паттерн проектирования, который позволяет копировать объекты, не вдаваясь в подробности их реализации.
А. Швец, «Погружение в паттерны проектирования», с. 118
Также известен как „Клон“. Формулировкой курса: логика клонирования — внутри самих клонируемых объектов.
4.2
Прототип

Скопировать «извне» не всегда возможно

часть состояния приватная, а копирующий код привязан к конкретному классу (книга, с. 119).

  • Объект, известный только по интерфейсу, так не скопировать
  • Аналогия книги (с. 122): деление клетки — оригинал сам участвует в создании копии
4.3
Прототип

Почему не вызвать конструктор

три причины по нарастающей.

  • 1Дублирование вызовов — решается методом расширения
  • 2Данные сокрыты или преобразованы конструктором — лишние операции и аллокации
  • 3Объект в иерархии — без знания типа не вызвать нужный конструктор: единственный выход

4.8
Прототип

Глубокая копия в коде

каждый элемент коллекции клонируется сам.

public class WrappedValue
{
public int Value { get; set; }
public WrappedValue Clone()
{
return new WrappedValue { Value = Value };
}
}
public class DeepCopyPrototype
{
private readonly List<WrappedValue> _values;
public DeepCopyPrototype(List<WrappedValue> values)
{
_values = values;
}
public DeepCopyPrototype Clone()
{
List<WrappedValue> values = _values.Select(x => x.Clone()).ToList();
return new DeepCopyPrototype(values);
}
}
На что смотреть
  • set здесь намеренно — иначе глубокая копия не нужна
  • В ЛР так не пишем: Do 10, Don't 20

    5.1
    Одиночка

    Одиночка

    Одиночка — это порождающий паттерн проектирования, который гарантирует, что у класса есть только один экземпляр, и предоставляет к нему глобальную точку доступа.
    А. Швец, «Погружение в паттерны проектирования», с. 133
    5.2
    Одиночка

    Две проблемы сразу

    Одиночка решает сразу две проблемы (нарушая принцип единственной ответственности класса).
    А. Швец, «Погружение в паттерны проектирования», с. 134
    Единственный экземпляр + глобальная точка доступа.
    5.3
    Одиночка

    Double checked lock

    вторая проверка — не создал ли объект другой поток, пока текущий ждал на lock.

    public class Singleton
    {
    private static readonly object _lock = new();
    private static Singleton? _instance;
    private Singleton() { }
    public static Singleton Instance
    {
    get
    {
    if (_instance is not null)
    return _instance;
    lock (_lock)
    {
    if (_instance is not null)
    return _instance;
    return _instance = new Singleton();
    }
    }
    }
    }
    C++C#Для C++-человека
    lock (_lock) { … } — как std::lock_guard на мьютексе; в .NET 9+ есть отдельный тип System.Threading.Lock.
    5.4
    Одиночка

    Одиночка через Lazy<T>

    потокобезопасность — забота Lazy<T>, не ваша.

    public class Singleton
    {
    private static readonly Lazy<Singleton> _instance;
    static Singleton()
    {
    _instance = new Lazy<Singleton>(() => new Singleton(), LazyThreadSafetyMode.ExecutionAndPublication);
    }
    private Singleton() { }
    public static Singleton Instance => _instance.Value;
    }
    C++C#Для C++-человека
    static Singleton() — статический конструктор: один раз, потокобезопасно, при первом обращении к типу — как static-переменная в функции в C++11.
    5.6
    Одиночка

    Режимы Lazy<T>

    полную потокобезопасность даёт только ExecutionAndPublication.

    Одиночка

    Решение: Singleton-лайфтайм в DI-контейнере

    «один на приложение» — настройка, а не свойство класса.

    services.AddSingleton<IClock, SystemClock>();
    На что смотреть
    • Класс обычный: публичный конструктор, зависимости аргументами, тестируется
    • Подробно DI-контейнеры — ЛР5

    Пять паттернов — пять вердиктов

    паттерн — не рецепт; у каждого своя цена.

    Паттерн
    Ситуация
    Вердикт
    Фабричный метод
    сценарий отличается только создаваемым типом
    почти антипаттерн: наследование, неявное нарушение SRP
    Фабрика
    то же — через композицию
    да: SRP, OCP, DIP
    Строитель
    много аргументов или пошаговая сборка
    да: Convenience или Stateful, никогда не храните готовый объект
    Прототип
    копия объекта, особенно в иерархии
    да: в C# часто достаточно record + with
    Одиночка
    один объект на приложение
    нет: Singleton-лайфтайм в DI-контейнере
