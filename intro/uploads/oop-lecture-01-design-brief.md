### Слайд 16 — Ссылки и значения
- **Визуал — код на весь слайд, разделённый на две половины подписями «ссылочный тип» / «значимый тип»**, и справа две мини-схемы памяти: в первой две переменные `a` и `b` стрелками указывают на один объект; во второй `p` и `q` — два отдельных прямоугольника.

```csharp
public record struct Coordinate(double X, double Y);   // struct — значимый тип

var a = new Point(1, 2);   // Point — class, ссылочный тип
var b = a;
b.MoveBy(10, 0);           // a.X тоже стал 11: a и b — один объект

var p = new Coordinate(1, 2);
var q = p;
q = q with { X = 11 };     // p.X по-прежнему 1: q — копия
```
- **Сноска «Для C++-человека»:** первый случай — как передача по указателю, только без `*` и `->`; второй — как обычная структура на стеке. `record struct` — короткая запись неизменяемой структуры с двумя полями и конструктором; `with` — копия с изменённым полем.
- **Строка снизу:** «Сущности предметной области — классы. Маленькие неизменяемые значения (координата, деньги, идентификатор) — структуры».

## Блок 3. Инкапсуляция + сокрытие = абстракция (слайды 24–28)

### Слайд 24 — Инкапсуляция
- **[ОПРЕДЕЛЕНИЕ] плашка (сверху):** Инкапсуляция — её суть заключается в объединении данных и поведений, оперирующих этими данными.
- **Блок кода:**
```csharp
public class Point
{
    public int _x;
    public int _y;

    public void MoveBy(int deltaX, int deltaY) { _x += deltaX; _y += deltaY; }
}
```
- **Сноска «Для C++-человека»:** `public` перед классом — видимость типа; тела методов пишутся прямо в классе; `_x` — принятое в C# именование приватных полей (здесь они пока публичные — намеренно).
- **Строка снизу:** «Ничто не мешает написать `point._x = 999` мимо `MoveBy`».

### Слайд 25 — Сокрытие
- **[ОПРЕДЕЛЕНИЕ] плашка (сверху):** Сокрытие подразумевает ограничение доступа к каким-либо данным или поведениям.
- **Блок кода**, подсветить строки со свойствами:
```csharp
public class Point
{
    public int X { get; private set; }
    public int Y { get; private set; }

    public void MoveBy(int deltaX, int deltaY) { X += deltaX; Y += deltaY; }
}
```
- **Сноска «Для C++-человека»:** `{ get; private set; }` — свойство: снаружи выглядит как поле (`point.X`), внутри — пара методов. Читать могут все, писать — только сам класс. Это замена паре `getX()` / `setX()` и главный инструмент сокрытия в C#.

### Слайд 26 — Друг без друга не работают
- **Визуал — два блока кода рядом, оба приглушённые, с подписями:**
  - «Инкапсуляция без сокрытия» — код со слайда 24, подпись «данные можно менять мимо методов».
  - «Сокрытие без инкапсуляции»:
```csharp
public class Point
{
    private int _x;
    private int _y;
}
```
    подпись «данные есть, сделать с ними ничего нельзя».
- **Строка снизу:** «Вместе — абстракция».

### Слайд 27 — Абстракция
- **[ОПРЕДЕЛЕНИЕ] плашка (крупная, это длинный текст — дать ей весь слайд):** Абстракция представляет собой чёрный ящик для её разработчика-потребителя, в том смысле, что её реализация для него недоступна, скрыта, он не обязательно знает какие именно данные используются для достижения поведений, предоставляемых абстракцией, так же, не может повлиять на эти данные напрямую, лишь через предоставленные поведения, отражающие определённые бизнес правила.
- **Под плашкой одна строка кода** и сноска:
```csharp
public double DistanceFromStart => Math.Sqrt(X * X + Y * Y);
```
- **Сноска «Для C++-человека»:** `=>` — метод/свойство из одного выражения; снаружи неотличимо от хранимого свойства. Потребителю всё равно — и в этом смысл.

### Слайд 28 — Account: правило живёт в одном месте
- **Визуал — код слева, три тезиса справа.** Код:
```csharp
public class Account
{
    public Account(double initialBalance) { Balance = initialBalance; }

    public double Balance { get; private set; }

    public bool Withdraw(double amount)
    {
        if (amount > Balance) return false;

        Balance -= amount;
        return true;
    }
}
```
- Подсветить `private set` и `return false`.
- **Справа:** «Правило в одном месте — обойти нельзя» · «Исключение не бросаем: это ошибка бизнес-логики, а не программиста (Don't 22)» · «Это и есть решение проблемы со слайда 23».

## Блок 4. Композиция (слайды 29–31)

### Слайд 29 — Типы и композиция
- Подзаголовок: «`Point` мы уже собрали из двух `int` — это композиция».
- **[ОПРЕДЕЛЕНИЕ] плашка:** Композиция — создание одних типов, на основе других, используя хранение их данных, как непосредственную часть описываемого объекта (композитный – состоящий из нескольких частей).
- **Строка снизу:** «Два вида — по тому, откуда берутся значения».

### Слайд 30 — Агрегация
- **[ОПРЕДЕЛЕНИЕ] плашка (сверху):** При агрегирующей композиции, значения получаются извне, их время жизни никак не привязано к объекту, частью которого они являются.
- **Блок кода:**
```csharp
public Point(int x, int y) { X = x; Y = y; }
var point = new Point(420, 69);
```
- **Сноска «Для C++-человека»:** конструктор без списка инициализации, присваиваем в теле; `var` = `auto`.

### Слайд 31 — Ассоциация
- **[ОПРЕДЕЛЕНИЕ] плашка (сверху):** При ассоциативной композиции значения создаются непосредственно при инициализации объекта, соответственно, время жизни таких объектов привязано к объекту, частью которого они являются.
- **Блок кода**, подсветить строку с `DistanceFromStart = …`:
```csharp
public class ImmutablePoint
{
    public ImmutablePoint(int x, int y)
    {
        X = x;
        Y = y;
        DistanceFromStart = Math.Sqrt(x * x + y * y);
    }

    public int X { get; }
    public int Y { get; }
    public double DistanceFromStart { get; }
}
```
- **Сноска «Для C++-человека»:** `{ get; }` без `set` — присвоить можно только в конструкторе; получаем неизменяемый объект без `const` на каждом поле.
- **Строка снизу:** «Выбор между агрегацией и ассоциацией — уже проектное решение: кто владеет значением и отвечает за его корректность?»

## Блок 5. Полиморфизм (слайды 32–36)

### Слайд 32 — Полиморфизм подтипов
- Подзаголовок: «Одна абстракция, несколько реализаций; код, работающий с абстракцией, не знает, какая реализация ему досталась».
- **[ОПРЕДЕЛЕНИЕ] плашка:** Полиморфизм — его суть заключается в отделении поведения абстракции от его реализаций.
- **Мини-схема справа или снизу:** один блок «абстракция» сверху, от него две стрелки к «реализация 1» и «реализация 2»; сбоку блок «код-потребитель» со стрелкой только к абстракции.

### Слайд 33 — Интерфейс
- **Блок кода:**
```csharp
public interface IPoint
{
    int X { get; }
    int Y { get; }
    double DistanceFromStart { get; }
}

public class Point : IPoint { /* как выше, + MoveBy */ }
public class ImmutablePoint : IPoint { /* как выше */ }
```
- **Сноска «Для C++-человека»:** `interface` — как класс из одних чисто виртуальных методов, но отдельная конструкция; `: IPoint` — «реализует»; реализовать можно сколько угодно интерфейсов. Префикс `I` — соглашение.
- **Строка снизу мелко:** «Пример учебный: в реальности для модели вроде точки абстракцию не выделяют».

### Слайд 34 — Два вида наследования
- **Две плашки [ОПРЕДЕЛЕНИЕ] рядом (две колонки):**
  - Реализация (наследование поведений) – используются интерфейсы, в C# реализовывать интерфейсы могут как классы, так и структуры. Говорят, что тип реализует интерфейс (класс `Point` реализует интерфейс `IPoint`).
  - Наследование (наследование реализаций) – используются классы, в C# одна структура не может быть унаследована от другой, либо от класса. Говорят, что класс является наследником другого класса, либо же его подклассом (класс `Cat` является наследником класса `Animal`).

### Слайд 35 — Наследование реализации
- **Блок кода**, подсветить `virtual`, `override`, `: base(name)`:
```csharp
public class Animal
{
    public Animal(string name) { Name = name; }
    public string Name { get; }
    public virtual void Voice() => Console.WriteLine("I am an animal!");
}

public class Cat : Animal
{
    public Cat(string name) : base(name) { }
    public override void Voice() => Console.WriteLine("Meow!");
}
```
- **Сноска «Для C++-человека»:** `virtual` знаком; `override` обязателен — без него компилятор скажет, что вы прячете метод, а не переопределяете; `: base(name)` — вызов конструктора родителя, как в списке инициализации. `abstract` — класс/метод без реализации, как чисто виртуальный.

### Слайд 36 — Объект
- Подзаголовок: «Теперь можно сформулировать».
- **[ОПРЕДЕЛЕНИЕ] плашка:** Объект, является набором атрибутов и поведений, реализация и данные которого сокрыта от конечного пользователя объекта. Фактически, объект является абстракцией, представляющий какой-то объект моделируемой предметной области.

## Блок 6. Наследование: где ломается (слайды 37–40)

### Слайд 37 — Наследование — механизм полиморфизма
- **Визуал — один тезис крупно:** «Наследование — не способ переиспользовать код, а механизм полиморфизма». Под ним: «Самая частая ошибка проектирования — перепутать одно с другим».

### Слайд 38 — Антипример из реальной лабораторной
- **Блок кода**, подсветить строку `public class Dealer : Deck` предупреждающим цветом:
```csharp
public class Deck
{
    public Deck(IReadOnlyCollection<Card> cards) { Cards = cards; }
    public IReadOnlyCollection<Card> Cards { get; }
    public void Shuffle() { /* ... */ }
}

public class Dealer : Deck
{
    public Dealer(IReadOnlyCollection<Card> cards) : base(cards) { }
    public void StartGame() { /* ... */ Shuffle(); /* ... */ }
}
```
- **Сноска «Для C++-человека»:** `IReadOnlyCollection<Card>` — коллекция только для чтения, обобщённый тип как шаблон.
- **Вопрос в зал крупно:** «Дилер — это колода?»

### Слайд 39 — is a / has a
- **Визуал — две колонки:**
  - Слева, перечёркнуто: «Наследование = „является“ (*is a*)». `Dealer : Deck` — «дилер *является* колодой?» — нет.
  - Справа, акцент: «Композиция = „имеет“ (*has a*)». Код:
```csharp
public class Dealer
{
    public Dealer(Deck deck) { _deck = deck; }
    private readonly Deck _deck;
    public void StartGame() { /* ... */ _deck.Shuffle(); /* ... */ }
}
```
- **Строка снизу:** «Сомневаешься — выбирай композицию. Это тема ЛР2».

### Слайд 40 — Правильное применение
- **Блок кода:**
```csharp
public abstract class Car
{
    public abstract void MoveTo(Coordinate coordinate);
}

public class Truck : Car
{
    public override void MoveTo(Coordinate coordinate) => Console.WriteLine($"Moving slowly to {coordinate}");
}

public class SportCar : Car
{
    public override void MoveTo(Coordinate coordinate) => Console.WriteLine($"Rapidly moving to {coordinate}");
}
```
- **Сноска «Для C++-человека»:** `$"..."` — интерполяция строк. `Coordinate` — та же `record struct` со слайда 16.
- **Строка снизу:** «Наследник *является* родителем с особым поведением — упор на изменение поведения».

### Слайд 46 — Три правила про форму
- **Визуал — три карточки:**
  - **Нейминг.** Английские общепринятые термины, без сокращений, транслитерации и машинного перевода; `Http`, не `HTTP`. Пример из документа (блок кода, приглушённо): класс `Thread` с методом `Join(Student)` для «подпотока» — читается как работа с потоками ОС.
  - **Никаких магических чисел** — именованные константы (Don't 2).
  - **Никакого мёртвого кода и комментариев к очевидному** (Don't 9, 10).

### Слайд 47 — DRY · KISS · YAGNI
- **Визуал — три колонки, YAGNI выделена акцентом:**
  - DRY — «не копируй — вынеси в метод».
  - KISS — «атомарные методы, не переусложнять».
  - YAGNI — «проектируйте ту предметную область, которая описана в задаче, а не ту, что может понадобиться».
- **Строка снизу:** «Вопрос „а что если VIP-счёт“ задают, чтобы проверить структуру, а не чтобы заранее реализовать».
